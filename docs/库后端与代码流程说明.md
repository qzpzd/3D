# 库后端与代码流程说明

这份文档解释三件事：

1. 哪些代码是标准算法、哪些是本项目自写的薄封装。
2. Open3D 和 PCL 如何安装、构建、运行，各自输入输出是什么。
3. 两张预览图的具体含义，以及为什么去平面后的工件看起来变了。

## 1. 三种传统处理后端

| 后端 | 入口 | 依赖 | 适用场景 |
|---|---|---|---|
| NumPy/SciPy/scikit-learn | `process` | 基础 Python 依赖 | 学习算法、无 Open3D/PCL 环境、快速原型 |
| Open3D | `process-open3d`、`align-open3d` | Python + Open3D | Python 研究基线、可视化、配准、点云算法验证 |
| PCL | `cpp/pcl_pipeline.cpp` | C++ + PCL + CMake | 产线 C++ 集成、大点云、成熟滤波器组合 |

三种后端使用相同概念：

```text
读取
→ ROI
→ 体素下采样
→ 统计/半径去噪
→ RANSAC 平面
→ 移除工装
→ 聚类
→ 目标工件
→ 法线/边缘/OBB
→ 配准或检测
```

默认 NumPy 后端被保留，是为了让流水线在没有 Open3D/PCL 的环境下仍能运行。量产时优先选择 Open3D 或 PCL。

## 2. 自研与调库的边界

算法不是本课题自创。工业界常用的实现方式如下：

| 功能 | 标准算法 | 当前 NumPy 基线 | Open3D/PCL 常用 API |
|---|---|---|---|
| ROI | 轴对齐裁剪 | `pass_through` | Open3D `crop`；PCL `PassThrough` |
| 下采样 | VoxelGrid | `voxel_downsample` | Open3D `voxel_down_sample`；PCL `VoxelGrid` |
| 孤立点去除 | SOR/半径滤波 | `statistical_outlier_mask` | Open3D/PCL `StatisticalOutlierRemoval` |
| 工装平面 | RANSAC + 平面模型 | `fit_plane_ransac` | Open3D `segment_plane`；PCL `SACSegmentation` |
| 工件聚类 | DBSCAN/欧式聚类 | scikit-learn `DBSCAN` | Open3D `cluster_dbscan`；PCL `EuclideanClusterExtraction` |
| 法线 | 邻域协方差 PCA | `estimate_normals` | Open3D `estimate_normals`；PCL `NormalEstimation` |
| OBB | 有向包围盒 | PCA-OBB 近似 | Open3D OBB；PCL `MomentOfInertiaEstimation` |
| 粗配准 | FPFH + RANSAC | 自写参考实现 | Open3D/PCL 特征与 RANSAC |
| 精配准 | ICP | 自写点到点 Kabsch-ICP | Open3D/PCL ICP |

项目自写的内容主要是：

- 把各步骤按工业流程串起来；
- JSON 参数、统计和输出组织；
- 无外部几何库的参考实现；
- 目标工件选择、OBB 裁剪和预览。

实际量产应优先使用库实现，因为库在二进制格式、并行、数值稳定性、百万点内存和可视化方面更成熟。

## 3. Open3D 后端

### 3.1 Open3D 是什么

Open3D 是 Intel 发起的开源 3D 数据处理库，对 Python 和 C++ 都有 API。它适合：

- PCD/PLY/OBJ 等点云和网格 I/O；
- 体素下采样、SOR/半径去噪；
- RANSAC 平面、DBSCAN 聚类；
- 法线、OBB/AABB；
- FPFH、RANSAC 粗配准、ICP；
- 交互式可视化和静态可视化。

Open3D 官方支持 Windows 10+ 64 位，当前 PyPI 支持 Python 3.10–3.14；本项目使用 Python 3.13 已实际验证。

### 3.2 安装

```powershell
cd C:\Users\18562\Documents\ChatGPT\3d
python -m pip install -r requirements-open3d.txt
python -c "import open3d as o3d; print(o3d.__version__)"
```

也可以只安装库：

```powershell
python -m pip install open3d
```

如果当前环境没有 GPU，Windows 的 `open3d` wheel 是 CPU 版本。不要把 Open3D 的安装和 Open3D-ML 混淆；本项目的异常检测使用的是 PyTorch 自建基线，不需要 Open3D-ML。

### 3.3 Open3D 传统流程

代码：[industrial_pc3d/open3d_backend.py](../industrial_pc3d/open3d_backend.py)

```powershell
python -m industrial_pc3d.cli process-open3d `
  --input outputs\demo\scene_raw.pcd `
  --config configs\traditional.json `
  --output outputs\open3d_demo
```

输入：

```text
outputs\demo\scene_raw.pcd
configs\traditional.json
```

输出：

```text
outputs\open3d_demo\
├── scene_raw.pcd
├── scene_roi_denoised.pcd
├── parts_without_plane.pcd
├── target.pcd
├── target_edges.pcd
└── open3d_summary.json
```

Open3D 负责：

```text
read_point_cloud
crop ROI
voxel_down_sample
remove_statistical_outlier / remove_radius_outlier
segment_plane
select_by_index
cluster_dbscan
estimate_normals
get_oriented_bounding_box
```

边缘提取复用 `geometry.extract_edges()`，因为 Open3D 没有跨版本统一的“一行缺陷边缘”接口。红色边缘包含高曲率和扫描边界，不能直接解释为缺陷。

### 3.4 Open3D 配准

```powershell
python -m industrial_pc3d.cli align-open3d `
  --source data\scan_001.pcd `
  --target data\template.pcd `
  --output outputs\open3d_alignment `
  --voxel-size 0.015
```

流程：

```text
体素下采样 + 法线 + FPFH
→ RANSAC 特征粗配准
→ point-to-plane ICP 精配准
→ 4×4 刚体变换
```

输出：

```text
source_aligned.pcd
transform_4x4.txt
open3d_registration_summary.json
```

配准只改变坐标系，不改变工件形状。它应在目标工件提取之后、CAD 测量或模板异常检测之前执行。

## 4. PCL 后端

### 4.1 PCL 是什么

PCL（Point Cloud Library）是大型 C++ 点云算法库，覆盖 I/O、滤波、特征、配准、分割、表面重建和可视化。相比 Open3D：

- C++ API 和现有机器人/视觉工程更贴近；
- 滤波器、分割器和特征模块多；
- 依赖和构建更复杂，Windows 下需要正确匹配架构、编译器、Release/Debug 和依赖 DLL。

### 4.2 Windows 安装：vcpkg 推荐

官方 PCL 文档推荐 Windows 使用 vcpkg。先安装 Git 和 Visual Studio 2022 C++ 工具链，然后：

```powershell
git clone https://github.com/microsoft/vcpkg.git C:\vcpkg
C:\vcpkg\bootstrap-vcpkg.bat
C:\vcpkg\vcpkg.exe install pcl:x64-windows
```

构建本项目：

```powershell
cd C:\Users\18562\Documents\ChatGPT\3d
cmake -S cpp -B cpp\build `
  -DCMAKE_TOOLCHAIN_FILE=C:\vcpkg\scripts\buildsystems\vcpkg.cmake
cmake --build cpp\build --config Release
```

如果使用 Visual Studio 生成器，程序通常在：

```text
cpp\build\Release\pcl_pipeline.exe
```

### 4.3 Windows/conda-forge 备选

如果已有 Anaconda/Miniconda：

```powershell
conda create -n pc3d-pcl -c conda-forge pcl cmake ninja -y
conda activate pc3d-pcl
```

然后在 Visual Studio Developer PowerShell 中：

```powershell
cmake -S cpp -B cpp\build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build cpp\build
```

如果 CMake 找不到 PCL，可显式传入 conda 环境中 PCL 的 `cmake` 配置目录作为 `PCL_DIR`。不同 PCL 版本的目录名可能不同，以 `conda info --envs` 和实际安装目录为准。

PCL 与编译器架构必须一致，不能把 x86 PCL 和 x64 程序混用。

### 4.4 Linux 安装

Ubuntu/Debian：

```bash
sudo apt update
sudo apt install -y libpcl-dev cmake build-essential
cd /path/to/3d
cmake -S cpp -B cpp/build -DCMAKE_BUILD_TYPE=Release
cmake --build cpp/build -j
```

### 4.5 PCL 运行

输入和输出：

```powershell
# Windows Release 生成器
cpp\build\Release\pcl_pipeline.exe `
  outputs\demo\scene_raw.pcd `
  outputs\pcl_demo `
  0.42 `
  0.0

# Ninja/单配置生成器
cpp\build\pcl_pipeline.exe `
  outputs\demo\scene_raw.pcd `
  outputs\pcl_demo `
  0.42 `
  0.0
```

参数：

```text
argv[1] 输入 PCD
argv[2] 输出目录
argv[3] 目标工件 x
argv[4] 目标工件 y
```

PCL 程序内部参数：

```text
ROI x/y/z       [-2,2] × [-2,2] × [-0.1,1.0] m
voxel size      0.012 m
SOR             20 neighbors, 2.5 sigma
plane threshold 0.006 m
cluster eps     0.035 m
min cluster     40 points
normal k        24
```

输出：

```text
parts_without_plane.pcd
target.pcd
target_with_normals.pcd
```

这些参数是合成场景的单位。换成毫米数据时必须同时修改 C++ 文件中的全部长度参数。为了保持代码简洁，PCL 示例使用少量固定参数和目标坐标，没有额外引入 JSON 解析依赖；生产版应把配置从外部文件加载。

## 5. 两张图怎么读

### 5.1 传统流水线预览

`outputs/demo/pipeline_preview.png` 有三幅：

1. **Raw scene**：完整合成工位，包含工装平面、背景点和两个工件。
2. **Clusters after plane removal**：去工装平面、降采样和 DBSCAN 后的两个工件簇。颜色是簇编号，不是缺陷类别。
3. **Selected part / edges**：选中目标工件；红点是高曲率或扫描边界点，不等于缺陷。

### 5.2 深度异常图

`outputs/deep_demo/anomaly_preview.png`：

- 颜色表示点级 PatchCore 异常分数；
- 越亮表示局部几何越偏离正常训练记忆库；
- 这张图只能定位异常，不能自动给出“凹坑/划伤/污染”类别；
- 标题中的阈值是点级阈值，物体级 NG 判定另用物体级阈值。

## 6. 为什么去工装后外形看起来不同

不是实体被重新建模，通常有五个原因：

1. **底面被一起删除**：RANSAC 删除距离工装平面阈值内的所有点，包括与平面重合的工件底面和低处侧壁。
2. **显示内容不同**：第一幅是完整场景，第三幅只显示一个目标工件。
3. **点密度降低**：体素下采样把多个点合成一个代表点，细节和连续性看起来会变化。
4. **去噪和聚类去除了点**：SOR、半径滤波和簇选择会删除孤立点或其他空间成分。
5. **自动缩放不同**：第一幅约 2.5 m 场景，第三幅约 0.4 m 工件，Matplotlib 的坐标范围和视角会改变视觉比例。

OBB 裁剪只过滤包围盒外点，不会主动压缩工件。当前默认合成演示中 OBB 前后都是 3,461 点，因此外形变化不能归因于 OBB。

如果工件底面是测量基准，不应只把平面点扔掉；应保留平面法向/距离作为基准，或只删除工件轮廓以外的工装点。如果只检测可见上表面，去掉底面通常没有问题。

## 7. 真实数据深度模型入口

`deep-demo` 只使用程序生成的合成数据。真实数据需要先运行 `process-open3d` 或 `process`，再对 `target.pcd` 做模板配准，之后调用 Python API：

```python
from industrial_pc3d.io import load_point_cloud
from industrial_pc3d.patchcore3d import PatchCore3D, PatchCore3DConfig

train_paths = ["data/normal/001.pcd", "data/normal/002.pcd"]
val_paths = ["data/normal_val/001.pcd"]
train_clouds = [load_point_cloud(path).xyz for path in train_paths]
val_clouds = [load_point_cloud(path).xyz for path in val_paths]

config = PatchCore3DConfig(voxel_size=0.01, patch_k=24, epochs=6)
detector = PatchCore3D(config, device="cpu")
detector.fit(train_clouds)
detector.calibrate(val_clouds)
detector.save("outputs/line_a/patchcore3d.pt")

test_cloud = load_point_cloud("data/test/001.pcd").xyz
result = detector.score(test_cloud)
point_scores = result["point_scores"]
object_score = result["object_score"]
```

输入要求：

- 与现场工件同类；
- 已完成标定和工装移除；
- 尽量对齐到同一模板坐标；
- 训练集只含正常件；
- 验证集也只用正常件标定阈值；
- 最终测试集必须独立。

模型输出的是一个物体异常分数和每点异常分数，不是已训练好的缺陷类别分类器。

## 8. 命令总览

| 命令 | 输入 | 输出 |
|---|---|---|
| `demo` | 内部合成场景 | 传统全流程、预览和统计 |
| `process` | 任意支持的点云文件 | 自研几何后端的 `target.pcd` 等 |
| `process-open3d` | 任意 Open3D 可读点云 | Open3D 后端目标点云和统计 |
| `align` | source + target | 自研 FPFH/ICP 对齐结果 |
| `align-open3d` | source + target | Open3D FPFH/ICP 对齐结果 |
| `registration-demo` | 内部合成源/模板 | 配准精度验证 |
| `deep-demo` | 内部合成正常/异常样本 | PatchCore 权重、指标、异常图 |
